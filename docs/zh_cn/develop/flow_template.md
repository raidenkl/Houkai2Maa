# 流程描述模板（给需求方 / 给 AI）

当你说「帮我做某个玩法」时，按这个格式描述一次即可，AI 就能直接产出 pipeline 节点。
信息不全时不要猜——缺少的部分标 `?`，AI 会回头问。

## 1. 玩法基本信息

| 项                           | 内容                            |
| ---------------------------- | ------------------------------- |
| 玩法名（英文，用于节点前缀） | 例：`SignIn`                    |
| 显示名（中文）               | 例：每日签到                    |
| 频率                         | 每天 / 每周 / 活动期间          |
| 是否默认勾选                 | 是 / 否                         |
| 前置条件                     | 例：需要先进入主界面 / 需要体力 |

## 2. 入口路径（从主界面开始）

逐层写「在哪个界面 → 点哪个东西 → 到哪个界面」，每一层给一条 720p 截图：

| #   | 当前界面 | 操作                 | 期望进入的界面 | 截图         |
| --- | -------- | -------------------- | -------------- | ------------ |
| 1   | 主界面   | 点左下角「签到」图标 | 签到面板       | `home.png`   |
| 2   | 签到面板 | 点「领取」按钮       | 领取动画       | `signin.png` |

## 3. 状态与分支

- 已领取/已完成时是什么样子？（按钮变灰？出现「已领取」文字？）→ 需要截图
- 有哪些弹窗会出现？（公告、网络错误、体力不足、双倍券）
- 失败时可以接受的处理：重试 / 跳过 / 停止？

## 4. 参数（交给用户配置的）

| 参数名       | 类型 | 默认值    | 说明               |
| ------------ | ---- | --------- | ------------------ |
| 刷本次数     | 整数 | 0（不限） | 0 表示一直刷       |
| 体力不足策略 | 单选 | 停止      | 停止 / 药剂 / 购买 |

## 5. 结束条件

- 什么情况算「完成」？（回到主界面？面板变灰？次数达标？）
- 什么情况必须「停止并报告」？（登录失效、活动已结束、体力耗尽）

## 6. 截图清单

每张截图要求：

- 1280×720（16:9）；
- 界面完整、无遮挡、无动画中间帧；
- 文件名写明场景：`signin-panel.png`、`farm-result.png`。

把截图放到 `debug/probe/`（或任意目录）并在上表写出文件名即可，
AI 会用 `tools/dev/crop.py` 裁剪模板并生成节点。

需要精确报坐标时加 `--grid` 生成带网格的截图（100px 一格、交点标坐标）：

```bash
python tools/dev/snapshot.py --image shots/signin.png --grid
# 产物：xxx-grid.png（网格）/ xxx-ocr.png（识别框）/ xxx-ocr.json（文字+坐标）
```
