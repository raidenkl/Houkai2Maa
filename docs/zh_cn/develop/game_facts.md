# 游戏事实表（game_facts）

> 本文件记录**实测**的游戏界面事实。所有坐标以 **1280×720（16:9）** 为基准。
> 未实测的项保持「待补」，禁止凭猜测填写。

## 采集方法

```bash
uvx maafw-cli connect adb 127.0.0.1:16384
uvx maafw-cli --json ocr                 # 文案 + 坐标 + 自动截图
uvx maafw-cli screenshot -o debug/probe/<场景>.png
```

截图后确认尺寸为 1280×720（`python -c "from PIL import Image; print(Image.open('x.png').size)"`）。

报坐标时建议让工具生成网格图，直接读刻度：

```bash
python tools/dev/snapshot.py --image shots/home.png --grid
# 输出 xxx-grid.png：100px 一格，交点标注 "x,y"
```

| 签到入口        | 待补 | —                                           | 待补（目前只在登录时弹窗）              | —                 |
| 邮件入口        | 待补 | —                                           | 待补                                    | —                 |
| 社团入口        | 待补 | —                                           | 待补                                    | —                 |
| 出击/关卡入口   | 待补 | —                                           | 待补                                    | —                 |

> **「主界面可交互」的判据**：左栏第 1 个图标模板。登录弹窗存在时整块左栏被暗色遮罩压平
> （NCC ≤ 0.37，甚至因无方差返回 -1），弹窗清完后为 0.91~0.95。顶部导航栏在弹窗下仍然可见，
> **不能**用「首页」判断是否可操作。
>
> 左栏图标是半透明的，底色会随主界面 CG 变化。裁模板要**只取白色图形本体**（含顶部灰条），
> 带上四周渐变背景会让分数从 0.95 掉到 0.87。多背景实测：`[36,154,30,40]` 最差 0.943
> （换看板后 0.912，故节点阈值放到 0.8）。
>
> 左上角玩家信息区（头像 / 等级 / 体力）整块可点，点开是「学生证」面板，范围至少到 y≈96，
> **不要**把它当成左栏图标区域。
>
> **小图标点击必须给固定 `target`（2026-10-19 实测）**。maafw 的 `Click` 不写 `target` 时
> 会在识别框内**随机取点**：同一个 [36,154,30,40] 的图标，日志里出现过 `point=[41,160]`
> （左上角边缘，点不中，任务 20s 后 `reco_timeout`）和 `point=[49,176]`（点得中）。
> 所以 `FamiliarExplore` / `ResonanceRefresh` / `WorldTravel` / `PowerBoost` 四个入口
> 统一写死 `"target": [51,174]`（图标中心）。
>
> **页面切换期间点击会被吞掉**。从子页面点「首页」回主界面后立刻点左栏图标，
> 点击发得出去但不生效（日志 `success: true`，页面却不动）；静止 2 秒后再点同一坐标即可进入。
> 串联流程里因此在每个步骤之间加了 `post_delay`。
> 注意 `DirectHit` 节点不会截图，所以对它设 `post_wait_freezes` 等于没生效。
>
> **`target_offset` 的基准同样是「识别框内随机点」，不是框中心或左上角（2026-10-20 实测）**。
> `PowerBoostFind` 命中说明文字框 `[406,504,321,24]`、offset `(471,19)`，日志里的点击点是
> `(1177,541)` = 随机点 `(706,522)` + offset；换个时刻同一节点点击点就变了。
> 框宽 321px，而「前往」按钮只有 ~90px 宽（约 1030~1120），所以 x 在 877~1198 之间抖，
> 有概率落到行内空白处 —— 表现是「点了没反应」，后面等下一个界面时 timeout。
> 对策见 §18：窄按钮要么写死 `target`，要么在偏移后加降级出口。

## 6. 使魔探险（FamiliarExplore，每日）

节点见 `assets/resource/pipeline/30_daily/FamiliarExplore.json`，实测于 2026-10-18。

### 6.1 入口与层级

| 步骤 | 界面     | 操作                                    | 判定特征                                       | 坐标（720p）            |
| ---- | -------- | --------------------------------------- | ---------------------------------------------- | ----------------------- |
| 1    | 主界面   | 点左栏第 1 个图标（有蓝点表示有新内容） | 模板 `30_daily/FamiliarExplore/entry_icon.png` | `[36,154,30,40]`        |
| 2    | 每日面板 | 点左侧「使魔探险」页签                  | OCR `使魔探险`，ROI `[0,345,145,70]`           | 页签框 `[24,363,99,34]` |
| 3    | 使魔探险 | 面板已就绪                              | OCR `已接取的探险数`，ROI `[200,125,360,55]`   | —                       |

> **页签不固定在「存在感」**：再次打开会停在上次看的页签，所以必须先判定再点「使魔探险」。
> 面板右上角常驻文案「使魔探险将于每日4:00刷新」（ROI `[600,108,680,92]`），可当「已在本页」的兜底判定。
> **该文案会随列表滚动上移**：列表在顶部时在 y≈150，滑到底时上移到 y≈117（x 从 906 → 672）。
> 早期用 `[780,130,420,50]` 只能框住靠下的位置，滑到底后识别失败，所以 ROI 要放宽到 y 108–200。

### 6.2 两种卡片形态

| 状态         | 界面特征                                           | 操作                                           |
| ------------ | -------------------------------------------------- | ---------------------------------------------- |
| 已完成待领取 | 卡片上有「探索完成」水印 + 右侧文字 `点击领取奖励` | 点 `点击领取奖励` → 弹「获得奖励」→ 点空白关闭 |
| 可接取       | 显示「需要时间：HH:00:00」+ 右侧 `点击选择使魔`    | 点 `点击选择使魔` → 进入派遣界面               |
| 进行中       | 显示「剩余时间：HH:MM:SS」                         | 不处理（识别不到上述两种文案即视为跳过）       |

两组按钮都在右栏 ROI `[900,150,380,560]` 内；OCR 能稳定读出（score≈1.0）。
**注意**：全屏 OCR 有时读不到这两个按钮（浅色字），必须限定 ROI。

### 6.3 派遣界面

| 元素     | 文案       | 坐标（720p）          | 备注                                           |
| -------- | ---------- | --------------------- | ---------------------------------------------- |
| 一键派遣 | OCR `派遣` | 框 `[768,617,124,37]` | 自动填满 4 个使魔位，成功率 0.00%→100%         |
| 出发     | OCR `出发` | 框 `[1032,615,69,40]` | 点击后回到使魔探险列表，该卡片转为「剩余时间」 |

> 一键派遣的 OCR 常把「一键派遣」读成「键派遣」（「一」字被按钮边吃掉），
> 所以 `expected` 只写 `派遣`，不要写完整词。

### 6.4 列表滚动

| 项         | 实测值（720p）                                                |
| ---------- | ------------------------------------------------------------- |
| 滑动       | `Swipe [640,620] → [640,250]`，duration 500ms，列表正常上滚   |
| 每次滚动量 | 约 1.5 张卡片（卡片高约 115px，间距 20px）                    |
| 到底表现   | 不再移动，右上刷新文案上移到 y≈117                            |
| 上限       | 节点 `FamiliarExploreScroll` 用 `max_hit: 4` 兜底，滑满即收尾 |

> 已接取 4/10 且无可领取/可接取卡片时，列表只剩「进行中」大卡（带 `剩余时间`），滑到底也不会出现按钮。
> 只有存在可接取卡片时才需要滚动，因此滚动节点放在 Claim/Select 之后、Done 之前。

### 6.5 已知限制

- `已接取的探险数 N/10` 在领取时会正常递减，但**派遣后不一定立刻 +1**，不能当计数依据。
- 领取时顶部会弹「任务已完成」横幅，属于瞬时提示，不需要处理。

## 7. 共鸣之力（ResonanceRefresh，每日）

节点见 `assets/resource/pipeline/30_daily/ResonanceRefresh.json`，实测于 2026-10-18。
任务描述：「刷新一次『共鸣屋』中的商品」，入口在「存在感」页签的任务列表里。

### 7.1 入口与层级

| 步骤 | 界面     | 操作                           | 判定特征                                           | 坐标（720p）                                  |
| ---- | -------- | ------------------------------ | -------------------------------------------------- | --------------------------------------------- |
| 1    | 主界面   | 点左栏第 1 个图标              | 模板 `30_daily/FamiliarExplore/entry_icon.png`     | `[36,154,30,40]`                              |
| 2    | 每日面板 | 点左侧「存在感」页签           | OCR `存在感`，ROI `[0,195,150,75]`                 | 页签框 `[33,220,76,27]`                       |
| 3    | 存在感   | 面板已就绪（右上角计分条）     | OCR `当前存在感`，ROI `[880,140,190,55]`           | —                                             |
| 4    | 存在感   | 点「共鸣之力」同一行的「前往」 | OCR `共鸣之力`（列表区 `[200,250,780,430]`）       | 标题框 `[402,305,130,40]` → 按钮 `(1037,385)` |
| 5    | 共鸣屋   | 点右上角圆形刷新按钮           | OCR `剩余次数N次`，ROI `[820,110,270,60]`          | `(1085,160)`                                  |
| 6    | 确认弹窗 | 点「确定」                     | OCR `免费刷新`（文案「你确定要进行免费刷新吗？」） | 确定 `(531,446)`、取消 `(752,447)`            |
| 7    | 主界面   | 点顶部「首页」                 | OCR `首页`，ROI `[615,50,80,50]`                   | 文字框 `[631,69,44,26]`                       |

> **「前往」不能用绝对坐标**：任务列表顺序会变（完成任务后该行消失，其余行上移），
> 所以用 OCR 识别标题框后叠加 `target_offset: [570,60,0,0]` 定位到同一行的按钮。
> `target_offset` 是 4 个整数（x/y 位移 + w/h），只写 2 个会被 schema 判「too short」。

### 7.2 关键行为

| 现象             | 实测结果                                                           |
| ---------------- | ------------------------------------------------------------------ |
| 完成后任务行     | **从存在感列表消失**（不是变成「已完成」），因此不会重复刷新       |
| 免费次数         | 显示在共鸣屋右上「剩余次数N次」，刷新一次减 1；为 0 时刷新要花水晶 |
| 刷新后提示       | 顶部弹「共鸣之力 任务已完成」横幅，**覆盖 y 0–105 约 2 秒**        |
| 横幅期间的导航栏 | 「首页」被遮住，OCR 会读成「巴完成」等噪音 → 必须等横幅消失再点    |
| 列表滚动         | 可滚，`Swipe [640,620] → [640,250]`；找不到任务时最多滑 4 次       |

> 防消费：`ResonanceRefreshFree` 只在 `剩余次数1次`~`剩余次数5次` 时点刷新；
> 识别到 `剩余次数0次` 走 `ResonanceRefreshNoFree` 直接收尾，不点刷新、不弹付费确认。

### 7.3 商店页兜底路径（暂未使用）

「共鸣屋」文字框 `[44,292,76,33]`）。任务入口走存在感更短，保留此路径仅作排查参考。

### 8.2 关卡图标为什么不能模板匹配

「使魔的爱」下方的关卡图标是**动态发光**节点（紫色球体有脉动光效），且会随解锁进度变化外观，
模板匹配不稳。改为 OCR 标签文字后**固定向下偏移 84px** 点击：

- 标签框中心 `(646,411)` → 图标中心 `(645,493)`，实测偏移 `[0,84,0,0]`；
- 图标白色外框实测 `x 589–700 / y 437–548`（含下方尖角到 y≈570），84px 落在框内居中位置。

### 8.3 关键行为

| 现象           | 实测结果                                                                  |
| -------------- | ------------------------------------------------------------------------- |
| 完成后任务行   | **从存在感列表消失**，同时列表顺序变化（累积消耗类任务的进度条会更新）    |

6. **验收**：用 `probe.py`（指向 PC 截图资源）确认关键模板命中分数 ≥0.9，

## 12. 启动/登录链（LaunchGame，2026-10-19 实测）

节点见 `assets/resource/pipeline/00_launch/LaunchGame.json` + `30_daily/SignIn.json`。

### 12.1 界面时序

| 阶段     | 画面特征                                                                        | 识别/操作                                   | 实测耗时         |
| -------- | ------------------------------------------------------------------------------- | ------------------------------------------- | ---------------- |
| 桌面     | launcher（无游戏文案）                                                          | `DirectHit` → `Shell` + `monkey` 拉起客户端 | 立即             |
| 更新检查 | miHoYo logo + 底部「检查资源文件更新：100%」                                    | 不操作，等标题画面                          | 20~90s（波动大） |
| 标题画面 | 「崩坏学园2」+ 底部「抚摸屏幕继续」（OCR `(549,648,245,45)`）+ 右上「账号切换」 | 点「抚摸屏幕继续」                          | 1~2s 进主界面    |
| 登录弹窗 | 每日签到 → 连登福利 → 活动广告 ×N → 公告板                                      | 见 §3                                       | 每个 1~3s        |
| 主界面   | 顶部导航 + 左栏图标（模板 0.91~0.95）                                           | 结束                                        | —                |

### 12.2 关键行为

1. **入口必须 `DirectHit`**：桌面（launcher）上没有任何游戏文案，用 OCR 文案做入口节点会
   直接判入口失败、连 `next` 都不执行（踩过：第一次录制 5 张截图就 failed）。用 `DirectHit`
   进入后再用 `next` 分流「标题画面 / 已在游戏内 / 需要启动」。
2. **`StartApp` 只填 `package` 不可用**：ADB 控制器上报
   `child return error [argv.exec=adb.exe] [argv.args=[... shell settings get secure android_id]]`
   后任务失败，实测改用 `Shell` + `monkey -p <pkg> -c android.intent.category.LAUNCHER 1` 正常。
3. **标题画面文案会延迟出现**：进入标题画面后的头几秒底部没有「抚摸屏幕继续」（截图可见），
   所以 `LaunchGameTitle` 的 `timeout` 给到 180s、`rate_limit` 1000，覆盖「更新检查 + 文案淡入」。
4. **签到弹窗只在当天未领时出现**：领完后重启不再弹（同一账号实测：首登有 2 个签到弹窗，
   重登只剩活动广告）。已领的日子在奖励格上盖「已领取」章。
5. **两个签到弹窗的「领取」按钮同坐标** `(941,500)`（框分别是 `912,483,61,35` /
   `910,483,63,35`），且连登福利标题带 `※` 装饰、OCR 不稳，故识别底部文案而不是标题。
6. **活动广告的 × 是同一素材**：两张不同活动图上的 × 像素级一致（NCC 0.996~1.0），
   位置随弹窗大小浮动（`1020,168` 附近），所以用模板匹配而不是固定坐标。
7. **公告板不一定会弹**：当天已读过就不再出现，节点保留 `max_hit 3` 兜底。

### 12.3 已知限制

- 账号登录/游客登录界面**未采集**，暂不做「检测到登录界面就停」的分支（标题画面右上只有
  「账号切换」，不属于登录界面）。换账号后需要补这一节。
- 签到 7 天全部领完、奖励重置后的形态未采集。
- 网络错误弹窗、版本更新弹窗未采集。

### 13.2 关键行为

1. **「今日免费 X/6」是剩余次数，不是已用次数**（2026-10-20 实测：4/6 打两场后变 2/6）。
2. **一次快捷战斗 = 3 场，但上限会被剩余免费次数压低**：弹窗里的次数框默认
   `min(3, 今日免费剩余)`（剩 2 次时弹窗直接显示 2），结算页按
   「第 N 次快捷战斗结果 / 战斗结算」分开列。
3. **免费次数用完的形态**：`今日免费 X/6` 整行**消失**，改显示 `消耗体力 35`，
   同时「快捷战斗」按钮**消失**，只剩灰色不可点的「选择助战好友」。
   **不存在「今日免费 0/6」这种写法**——收尾判据要用「消耗体力」。
   `WorldTravelDetail` 的 next 里要把 `WorldTravelNoFree` 排在 `WorldTravelQuick` 前面，
   否则按钮还没消失的那一帧会点进去花体力打本。
4. **存在感任务只要求挑战 1 次**，所以打完一轮「世界这么大」就从列表消失，
   但「今日免费」通常还剩 2~5 次。**入口必须有第二条路**：顶部「战斗」页签
   直接就是虚轴之庭关卡选择页（不出现在存在感里也能进），
   见 `WorldTravelBattleTab`。旧版只走存在感，任务行一消失就整条收尾，
   剩下的免费次数永远刷不掉。
5. **关卡会随进度改名**：连打 3 场后从 `阿兹塔·碎岩` 变 `阿兹塔·大地`（进度：阶段二），
   界面结构不变，所以不要写死关卡名。
6. **任务完成后该行从存在感列表消失**（与共鸣之力/火线救援一致），列表顺序同时变化。
7. **结算页「确定」位置随条目数上下浮动**：行数多时 `(760,599,53,31)`，少时会到
   `(786,614)` 附近。roi 要给足纵向余量（现用 `[680,540,320,130]`），
   否则条目少的那一轮识别不到确定 → 确定没点上 → 整个循环断掉。
8. **结算页是半透明盖在关卡页上的**：底下的「选择助战好友 / 快捷战斗」文字仍能被 OCR 读到。
   点「确定」后必须 `post_delay` ≈1500ms 让它淡出，再判「战斗结算」还在不在，
   否则会把半透明的结算页误判成详情页（旧版因此每轮只打一次就回主界面）。
9. 关卡选择页与详情页**无法用『虚轴之庭』/『家园』区分**：详情页背景是同一张地图，
   OCR 照样读得到。所以别做「页面二选一」判定，直接按流程顺序推进（前往 → 出击 → 详情）。

### 13.3 已知限制

- 「今日免费」与体力之间的折算关系未实测（免费次数期间体力全程没变，
  用完后的「消耗体力 35」没有真的点进去验证）。
- 阶段切换后是否需要重新选关未实测。

### 16.2 关键行为

1. **点左侧角色头像 = 切换到备用装备套装 = 自动战斗**。备用套装里带自动开火装备，
   切过去后**不需要任何操作**，约 10~20s 自动清场到结算页（含通关演出）。
   不切的话角色站桩不动，约 70s 会被怪打死，弹「救救我」。
   切换前 HP `15179/15179`、弹药 `20/20`；切换后 HP `16038/16038`、弹药 `306/326`——
   这两组数字可作为「切没切成」的旁证。
2. **「再次挑战」回到的是助战好友列表**，不是直接开战。所以循环是
   `结算 → 勾券 → 再次挑战 → 备用装备 → 开战 → 点头像 → 结算`。
3. **双倍券勾选框每次都重置为未勾选**：备战页两次实测、结算页三次实测（其中一次上一轮
   确实用了双倍券，票数 99→98，结算页框仍是空的）。因此两处都要「先判形态再点」，
   用 `coupon_on/off`、`again_on/off` 四个模板判别；四个模板交叉实测均为
   「本状态 1.0 命中、另一状态 miss」。
4. **勾了双倍券后「消耗体力」翻倍**：`消耗体力 50` → `消耗体力100`（OCR 也从两段
   合并成一段）。这是它唯一的文字副作用。
5. **点「战斗」页签会回到上次停留的关卡页**，不是活动列表。所以必须用右上横幅
   （= 当前活动名）校验是不是要刷的活动；不对就点横幅回活动列表（实测可回）。
6. **BONUS 关卡在活动关卡列表的最后一页**（海妖秘境是 2/2），页标 `N/N` 表示已是末页。
7. **体力不足的信号与顺序**（2026-10-19 复测修正）：
    - 备战页右下按钮从 `选择助战好友` 变成 **`补充体力`** `(730,648)`，这是最早的信号；
    - **点它不会直接扣水晶**，而是先弹确认窗。弹哪个取决于双倍体力余量：
        - 还有双倍体力 → **`兑换双倍体力`**（标题 `(639,251)`，说明
          「主人可兑换1双倍体力，补充2体力」，按钮 `兑换 (532,458)` / `取消 (745,458)`）；
        - 双倍体力为 0 → **`补充体力`**（「主人可花费60水晶，补充205体力」，只有 `取消 (745,458)`）。
    - 兑换**只补 2 点体力**，用掉 1 张双倍体力券。BONUS 关要 50 点，所以兑换完仍然不够，
      会紧接着弹水晶窗。因此脚本里的兑换上限设 **1 次**：再多换只是把券一张张换成 2 点体力。
    - 水晶窗一律 `取消`（实测取消后水晶数 62246 未变），绝不点「确定」。
    - 结算页点「再次挑战」时体力不足，同样按这个顺序弹窗。
8. **死亡弹窗「救救我」**：`确定` 是花 60 水晶复活，安全出口是 `返回` `(529,639)`，
   接着弹 `退出关卡` 确认，点 `确定` `(532,455)` 才真正退出。

### 16.3 已知限制

- **活动名要能 OCR**。活动标题是美术字时会被拆开：实测「海妖秘境」读成「海妖」
  「秘境」两段，所以填整名匹配不到。这种情况下填其中一个词（如「海妖」）即可，
  因为 `expected` 是正则搜索。当前无法自动合并相邻 OCR 框。
- 活动名通过 `option: ActivityName`（`type: "input"`，占位符 `{活动名}`）注入，
  `tools/dev/replay.py` 不支持注入选项值，所以**没有为这条链出回放用例**；
  回归覆盖改用 `tests/node-cases/activity-farm.json`（14 张截图 × 不依赖选项的节点）。
- BONUS 关的「最后一页」假设只在海妖秘境验证过；若某活动 BONUS 不在末页，
  需要补充翻页策略。
- 只支持「备用装备套装里带自动战斗装备」的账号配置；若备用套装没配自动武器，
  切过去也不会自动清场。
- 结算页背景是半透明的，关卡页的 `战况` 仍可 OCR，所以节点顺序必须把
  `ActivityFarmResult` 排在 `ActivityFarmStage` 之前。

## 17. 一键日常（OneClickDaily，编排层）

节点见 `assets/resource/pipeline/30_daily/OneClickDaily.json`，声明见
`assets/tasks/oneclick/OneClickDaily.json`，实测于 2026-10-19（1280×720，emulator-5554 官服）。

### 17.1 结构

- 8 个 `OneClickDaily*Gate` 分流闸，默认 `DirectHit`，`next` 指向下一个 Gate（= 跳过）；
- 8 个 `checkbox` case，勾选时用 `pipeline_override` 把对应 Gate 接到业务 `Entry`；
- 各链路原本 `next` 为空的收尾节点在 **task 级 `pipeline_override`** 里接到下一个 Gate；
- 顺序：启动（含签到）→ 使魔探险 → 共鸣之力 → 火线救援 → 世界这么大 → 战力补强
  → 社团领体力 → 活动清体力。活动清体力默认不勾（吃光体力且要填活动名）。

### 17.2 串联时必须处理的三个真实行为

1. **不是所有收尾节点都回主界面**。`ResonanceRefreshHome` / `FireRescueHome` /
   `WorldTravelHome` / `PowerBoostHome` / `ClubStaminaHome` 会点一次「首页」，
   但 `FamiliarExploreDone` 只做 `DoNothing` —— 串到它之后会**停在使魔探险页**，
   下一步的左栏图标入口全部识别失败。中间必须补一个点「首页」的节点
   （`OneClickDailyHomeFromFamiliar`）。
2. **点击会被页面切换吞掉**。从子页面点「首页」回到主界面，0.6s 内去点导航栏或左栏图标，
   框架日志显示 `success: true`，但页面不动。实测：
    - `ResonanceRefreshEntry` 命中并点击后 20s 内没进页面，最后 `reco_timeout`；
    - `ClubStaminaSocialTab` 点了「社交」，画面仍停主界面。
      对策：每个步骤开始前**主动点一次「首页」**，再等 1.5s 才进业务节点。
      该等待是固定延迟 —— 主界面在页面切换完成后没有可靠的「可交互」信号可用。
3. **左栏图标出现 ≠ 可交互**。图标是淡入的，模板 0.8 在淡入早期就能匹配上
   （实测 0.927），但此时页面仍在锁输入。所以不能拿「图标出现」当就绪判据，
   `post_wait_freezes` 也无效：`DirectHit` 不截图，拿不到新帧。

另有一个通用坑见 §2：**小图标点击必须给固定 `target`**，否则默认随机点会落到边缘。

## 18. 框架语义备忘（2026-10-20 实测踩出来的）

这几条不是游戏事实，但直接决定流程能不能跑通，写流水线时必须记住。

### 18.1 限制「在 next 里等多久」的是**当前节点**的 timeout

`next` 候选自己写的 `timeout` 不参与等待上限。`LaunchGameStart` 的 next 里
`LaunchGameTitle` 写了 `timeout: 180000`，但 `LaunchGameStart` 自己是默认 20000，
结果冷启动过 miHoYo logo 时 20s 就被判 `Task timeout`，任务直接中止。

> 规则：**凡是 next 里要等一个慢界面（启动/加载/结算），父节点必须自己放大 timeout**。
> 现用：`LaunchGameStart.timeout = 180000`、`*Find.timeout = 6000`（等页面跳转）。

### 18.2 `next` 全部失败 ≠ 立刻失败，而是重试到 timeout

`OneClickDailyEntry` 原本 `next: [NavHome(OCR), [JumpBack]CommonRewardPopup]`。
在桌面上两个都识别不到，框架**不会**立即判定失败，而是把整个列表反复重试到
timeout（20s）才报 `bad next`，表现为「点了任务后干等 20 秒什么都不做」。

> 规则：**next 列表末尾要有一个 DirectHit 兜底**，串行判定下 OCR 失败后它立刻接住。
> 兜底节点**不能排前面**，否则永远轮不到 OCR 候选。

### 18.3 `on_error` 对「作为 next 候选时」的识别失败无效

`NavHome` 上写的 `on_error: [Resume]` 永远不会触发 —— 它只作为 next 候选参与识别，
不是当前节点。`PowerBoostFind` 这类节点靠 `on_error` 兜底同样不可靠。

> 规则：**降级要写进 next 的候选列表**（如 `next: [Shop, Done]`），不要指望 on_error。
> `on_error` 只在节点自己作为当前节点、且动作/识别失败时才有机会生效。

### 18.4 跳转/滚动后立刻识别，会拿到「运动中的坐标」

`PowerBoostShopScroll`（swipe 500ms）之后紧接着识别「×0」，拿到的是惯性滚动中的
位置，和稳定后差 37px，点击就落到按钮之外（点了没反应）。

> 规则：**滚动/跳转后的第一个识别节点加 `pre_wait_freezes`**（现用 300ms，
> target 限定在会动的区域），或让上一个节点带 `post_wait_freezes`。
> 但别给「搜索型 Scroll」本身加 `post_wait_freezes`：回放会因截图帧数浮动而失败。

### 18.5 窄按钮不要只靠 `target_offset`

`target_offset` 以识别框**内随机点**为基准（见 §2），框宽决定抖动范围。
「前往」按钮 ~90px 宽，若锚在 300px 宽的说明文字上，必然有概率点空。

> 规则：**位置固定的窄按钮写死 `target` 绝对坐标**；位置会变的（列表行）
> 用「OCR 锚点 + offset + 降级出口」，并在 next 里补一个「点不进去就收尾」的候选。
